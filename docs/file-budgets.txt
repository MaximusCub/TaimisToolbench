# Per-file line budgets - a ratchet, not a target.
#
# Why this file exists: Views/CraftingPlanView.cs was decomposed from
# ~4,802 lines to ~2,802 in July 2026, and was back over 5,200 by the
# following August - +2,156 lines in 33 days, past its own
# pre-decomposition baseline - while docs/ROADMAP.md still called the
# decomposition complete. Nothing detected it, because the mechanism that
# produced the 2,802-line result was social, and social mechanisms do not
# survive contact with an agent loop.
#
# How to read it: every entry is the file's size on the day it was added.
# CI fails when a file exceeds its entry. Nothing here is a goal to
# optimise towards and no entry means "this file should be this long" -
# growth is simply not free any more. It costs one deliberate line in this
# file, in the commit that grows the code, where a reviewer can see it.
#
# Lowering a budget is the explicit act of a refactor commit. Raising one
# is allowed, and should say in the commit message why the code earned it.
#
# Every tracked .cs file is gated, listed here or not. A file with no entry
# is held to the default below. The entries are the exceptions: files that
# are allowed to be longer than the default, each at the size it was on the
# day its entry was added. An entry whose path no longer exists also fails,
# so a rename has to re-anchor its budget rather than silently drop it.
#
# default 300
#
# Where 300 comes from, over the 734 tracked .cs files on 2026-09-06. It is
# the 75th percentile of their line counts, which is 290, rounded up to a
# multiple of 50. It is also where the count of files over the line stops
# falling quickly: 150 lines catches 378 files, 200 catches 300, 250
# catches 225 and 300 catches 180, after which each further 50 lines takes
# out at most 30 more. Three quarters of the tree is under it and a quarter
# is over, so it binds on a file that has grown without binding on ordinary
# code.
#
# An entry below the default still binds at the entry, not at 300. Nothing
# here got looser when the default arrived, and an entry under 300 is not
# redundant: on the same date, dropping the 499 entries at or under 300
# would have handed those files 83,161 lines of free growth between them.
#
# Format: <path> <max-lines>. Seeded 2026-08-25 from the tree at that
# commit (git ls-files '*.cs' | xargs wc -l).
#
# The gate is FileLineBudgetTests in tests/TaimisToolbench.Tests. It walks
# the tree, so it sees a file with no entry; the "Files stay within their
# line budgets" step in .github/workflows/tests.yml walks this file instead
# and so can only check the entries, which is a subset of the same rule.
